### Decisoes Tecnicas Tomadas
1. **Role lida do banco (user_profiles.role)** — user_metadata do Supabase não é persistido de forma confiável na criação manual de usuários via Dashboard. Solução: fetchProfile() após cada auth state change.
2. **Singleton Supabase via globalThis** — Vite HMR recria módulos, gerando múltiplas instâncias do cliente e conflitos de Navigator Lock.
3. **Bypass Navigator Lock (`auth.lock: fn => fn()`)** — múltiplas abas competem pelo lock `"lock:sb-...-auth-token"` durante inicialização. A aba perdedora não restaura sessão e é redirecionada a /unauthorized. Bypass elimina a disputa sem comprometer a integridade para este caso de uso.
4. **Retry x3 no fetchProfile** — fallback para erros transitórios de lock antes do bypass ser aplicado (defesa em profundidade).
5. **`(supabase.from(...) as any)` pattern** — TypeScript do supabase-js não infere tipos de JOINs. Workaround deliberado; corrigir futuramente com `supabase gen types`.
6. **Alert pipeline automático** — `useAddVitalSigns` cria registro na tabela `alerts` quando limites são ultrapassados (spo2<92, sistólica>160/<90, FC>100/<50, temp>37.8, glicemia>180/<70). Familiar vê em tempo real via `usePatientAlerts`.
7. **refetchInterval: 30000** em `usePatientActiveShift` — polling a cada 30s para o painel familiar enquanto Realtime subscriptions não são implementadas.
